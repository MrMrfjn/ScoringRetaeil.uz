## 3. Новый блок «Слабые места филиала» на Дашборде

Этот блок опирается на текущую сводку по филиалам (пример из Excel‑таблицы: Ф‑1..Ф‑7, портфель, просрочка, «Хатар» %) и добавляет **детальную декомпозицию просрочек по клиентским признакам**.

### 3.1. Цель блока

- Показать **руководству сети**:
  - какие филиалы **протекают по деньгам** (частная «прибыль» и утечки по просрочкам);
  - где **самая болезненная просрочка** по:
    - полу,
    - возрастным группам,
    - региону / МФЙ,
    - типу дохода.
- Сформировать **индивидуальные задачи для каждого филиала**, которые можно визуально показать на собрании.

### 3.2. UI: новый блок на Executive Dashboard

- [x] На главном экране (Executive Dashboard) добавить раздел:

> **«Слабые места филиалов»**

- [ ] Состав блока:
  1. **Таблица по филиалам** (строки Ф‑1…Ф‑7):

     | Филиал | Портфель | Просрочка (долг) | Хатар % (риск) | Потенц. утечка прибыли (оценка) |

     - Портфель и Просрочка — уже есть (как в Excel‑примере).
     - Хатар % — NPL или доля просроченного долга.
     - Потенциальная утечка прибыли — приближённая оценка:
       - формула: `просрочка * маржа` (маржу можно задать константой в настройках, напр. 20%).

  2. **Для выбранного филиала** (клик по строке) — подробный блок:

     - мини‑KPI:
       - доля просрочки в портфеле,
       - доля долга ≥ 4 млн,
       - сравнение с средним уровнем сети;
     - 4 подтаблицы / мини‑чарта:

       - **По полу**:

         | Пол | Клиентов | Договоров | Долг (всего) | Долг ≥ X | NPL % |

       - **По возрасту (диапазоны)**:

         | 18–25 | 26–35 | 36–45 | 46–55 | 55+ |
         |---|---|---|---|---|
         (для каждого — клиенты, договоры, долг, NPL %)

       - **По региону / МФЙ** (филиал‑локальный срез):

         | Регион | МФЙ | Клиентов | Долг (всего) | Долг ≥ X | NPL % |

       - **По типу дохода**:

         | Тип дохода (госслужащий, предприниматель, пенсионер, частный) | Клиентов | Долг (всего) | NPL % |

- [x] Вверху блока добавить фильтр **«Период просрочки»**:
  - Формат: `От дата` — `До дата` или готовые пресеты:
    - «последние 30 дней»,
    - «последний квартал»,
    - «год».
  - Параметры уходят в запросы для расчёта просрочек.

### 3.3. SQL‑уровень

- [ ] Для каждого филиала:

```sql
-- Базовая сводка по портфелю и просрочке
SELECT
  branch,
  COALESCE(SUM(product_amount), 0) AS portfolio,
  COALESCE(SUM(debt_amount), 0)    AS overdue,  -- можно ограничить по DPD>0
  ROUND(
    100.0 * SUM(CASE WHEN status_detail IN ('Ёмон','МИБ','Судда') OR total_late_days >= 90 THEN 1 ELSE 0 END)
    / NULLIF(COUNT(*), 0),
    2
  ) AS risk_pct
FROM contracts
WHERE contract_date BETWEEN :date_from AND :date_to
GROUP BY branch;
```

- [ ] По полу / возрасту / типу дохода / региону / МФЙ:
  - использовать join `contracts` → `clients` по `client_id`;
  - группировка соответственно по `gender`, возрастным бинам, `income_source`, `region`, `mfy`.

### 3.4. Аналитика и выводы для филиалов

- [x] Для выбранного филиала построить **rule‑based выводы**, например:
  - «В филиале Ф‑2 60% долга ≥4 млн у клиентов 26–35 с типом дохода «предприниматель»».
  - «У женщин 36–45 в регионе X, МФЙ Y NPL 28% — выше среднего по сети на 10 п.п.».
  - «Основная боль филиала Ф‑3 — предприниматели с долгом 4–8 млн в МФЙ Z».
- [ ] Визуально оформлять выводы в виде списка карточек (иконки 🔴🟡🟢 для уровня риска).

## Жёсткие правила

1. **Каждый ТЗ-файл = одна законченная задача.** Задача считается выполненной, только когда **все чекбоксы** в файле закрыты (`[x]`).
2. **Не пропускать подзадачи.** Если написано «проверить на всех страницах» — значит проверить на **каждой**: `/`, `/portfolio`, `/intelligence`, `/alerts`, `/import`, `/developer`, `/admin`, `/scoring`.
3. **Производительность — абсолютный приоритет.** Если blur или анимация вызывает лаг на странице с таблицей 500+ строк — **убрать или уменьшить**. Ни один визуальный эффект не стоит потери отзывчивости.
4. **Не ломать логику.** Все SQL-запросы, роуты, RBAC, формы, CSRF — оставить как есть. Менять **только CSS, HTML-разметку шаблонов и минимальный JS** для анимаций/переключений.
5. **После каждого ТЗ — регресс.** Запустить приложение (`python main.py`), пройти по всем страницам, убедиться что ничего не сломано и не тормозит.
6. **Отмечать прогресс.** После выполнения каждого ТЗ — в самом файле ТЗ заменить `[ ]` на `[x]` у всех выполненных пунктов. Частично выполненные — `[~]`.

## Как работать

1. **Прочитай текущий файл ТЗ** целиком.
2. **Прочитай текущий код** (CSS, NAV, нужный шаблон) — через `Read` или `Grep`.
3. **Вноси изменения** через `StrReplace` — аккуратно, не теряя существующую разметку.
4. **Проверяй линтер** (`ReadLints`) после каждого крупного изменения.
5. **Тестируй** — запусти `python main.py`, открой страницу в браузере, проверь визуально.
6. **Отметь чекбоксы** в файле ТЗ.
7. **Переходи к следующему ТЗ.**
